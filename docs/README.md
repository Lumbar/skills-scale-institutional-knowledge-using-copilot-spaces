# OctoAcme Project Management Docs

This README indexes OctoAcme's project management process documents and provides a short summary of our approach so team members can quickly find the right guidance.

## Summary of OctoAcme project management processes

OctoAcme runs work with a customer-first, data-informed, and iterative delivery model. Every project has clear ownership, a predictable communication rhythm, and a lightweight set of artifacts that keep teams aligned from kickoff through release and retrospective.

- Customer-first delivery: prioritize customer value, usability, and measurable outcomes.
- Clear ownership: each project has a named Project Manager (PM) and Product Lead, with delivery work owned by the team.
- Iterative execution: break work into small, testable increments and learn from evidence.
- Structured lifecycle: initiation, planning, execution, release, and close & retrospective.
- Regular cadence: daily standups, weekly delivery syncs, sprint demos, and stakeholder updates.
- Core artifacts: project one-pager, roadmap/release plan, backlog with acceptance criteria, risk register, and retrospective action items.

## Project management lifecycle

1. Initiation: validate problem, stakeholders, and success criteria.
2. Planning: define scope, milestones, dependencies, and backlog.
3. Execution: build, test, review, and iterate with visible progress tracking.
4. Release: deploy with verification, release notes, and stakeholder communication.
5. Close & retrospective: capture learnings and identify follow-up improvements.
